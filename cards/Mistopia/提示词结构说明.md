# Mistopia 提示词结构说明

这份项目现在分成两层：

## 工程控制层

位置：

- `.cardrc.json`
- `cards/Mistopia/tavern-cards-state.json`

这些文件给 `tavern-cards-forge.mjs` 读取，用来决定世界书怎么生成、怎么触发、插入在哪里。

常见工程 key：

```yaml
projectName: 项目名称
worldbookName: 世界书名称
form: charactercard / worldbook
mvu: 是否使用 MVU
entryManifest: 世界书条目注册表
typeLists: 条目类型排序
strategyThresholds: 蓝灯 / 绿灯 / 向量化推导规则
partOrder: 同类型条目的排序规则
first_messages: 开场白文件路径
```

`entryManifest` 里面常见 key：

```yaml
abstract: 条目摘要，给工程索引和调试用
contents: 按顺序拼接正文片段
path: 直接读取某个正文文件
file: contents 片段中的正文文件路径
content: contents 片段中的内联文本
keywords: 绿灯触发关键词候选
part: 同类型下的子类
scope: catalog / specific
rephrase: 是否为重述或修正规则
strategy: configure 后推导出的触发策略
position: configure 后推导出的插入位置
```

这些 key 需要保持英文，因为 mjs 按这些字段读取。

## 世界书正文层

位置：

- `cards/Mistopia/世界书/世界观/*.yaml`
- `cards/Mistopia/世界书/扮演准则/*.yaml`
- `cards/Mistopia/世界书/势力/*.yaml`
- `cards/Mistopia/世界书/组织/*.yaml`
- `cards/Mistopia/世界书/怪物生态/*.yaml`

这些文件里的内容会被 `entryManifest.contents` 或 `entryManifest.path` 读出来，原样拼进 SillyTavern 世界书条目。

所以正文文件里不要再写旧结构：

```yaml
meta:
runtime:
content:
```

如果正文文件里写了 `content:`，它不是给 mjs 看的控制字段，而是会作为普通文本进入世界书 prompt。

新版正文推荐直接使用中文 key-value：

```yaml
---
雾冕诸邦:
  核心定位:
    - ...
  魔导科技:
    - ...
  长期争议:
    - ...
```

细标签和单文件宏观标签通常不写在正文文件里，而是在 `tavern-cards-state.json` 的 `contents` 里包：

```json
{
  "contents": [
    { "content": "<世界主设定>" },
    { "file": "世界书/世界观/世界主设定.yaml" },
    { "content": "</世界主设定>" }
  ]
}
```

最终进入世界书的大概效果会是：

```yaml
<世界主设定>
---
雾冕诸邦:
  核心定位:
    - ...
</世界主设定>
```

大型世界书的大类标签采用包装条目：

```yaml
世界书/势力/➡️势力开始.yaml: <势力>
世界书/势力/➡️势力结束.yaml: </势力>
世界书/组织/➡️组织开始.yaml: <组织>
世界书/组织/➡️组织结束.yaml: </组织>
```

中间的 `scope: specific` 详情条目只注册正文文件，不再各自重复包 `<势力>`、`<组织>` 等大类标签。包装条目、概览条目、详情条目依靠同一 position 下的 order 排序。

## 以后从哪里开始改

改设定正文：

- 从 `cards/Mistopia/世界书/` 开始

改条目触发词：

- 改 `cards/Mistopia/tavern-cards-state.json` 里的 `entryManifest.*.*.keywords`
- 或用 forge patch

改蓝灯 / 绿灯 / 向量化规则：

- 改 `strategyThresholds`
- 谨慎处理 `configure`：本项目的势力、组织依靠手动 order 包装，configure 会重新分配 order，运行后必须重新检查并固定包装区间

改世界书条目顺序：

- 改 `typeLists`
- 同类型内改 `partOrder`
- 手动检查 `position.order`
- 不要随便使用 `configure` 或 `configure --force` 覆盖本项目 order；势力和组织的大类标签依靠 `➡️开始` / `➡️结束` 的 order 范围包住详情

改开场白：

- 改 `cards/Mistopia/开场白/0.txt`

旧根目录 `worldbook/` 目前只当迁移参考，不再作为正式世界书源文件。
